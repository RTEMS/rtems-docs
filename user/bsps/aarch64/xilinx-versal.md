# Qemu Xilinx Versal

This BSP supports three variants: `versal-qemu`, `versal-aiedge` and
`versal-vck190`. The basic hardware initialization is performed by the
BSP. These BSPs support the GICv3 interrupt controller present in the Xilinx
Versal Adaptive Compute Acceleration Platform (ACAP) systems. The BSPs
currently only work when started in the secure mode.

The `versal-aiedge` BSP variant has been tested on:

- `Trenz TE0950` (uses secondary serial peripheral)

## Clock Driver

The clock driver uses the `ARM Generic Timer`.

## Console Driver

The console driver supports the default Qemu emulated ARM PL011 PrimeCell UART.
There are some differences between the PL011 and the UART used by actual Versal
ACAP hardware systems.

## Running Executables on QEMU

ELF executables generated by these BSPs can be run using the following command:

```shell
qemu-system-aarch64 -no-reboot -nographic -serial mon:stdio
 -machine xlnx-versal-virt -m 4096 -kernel example.exe
```

## Running Executables on Hardware

On hardware, RTEMS can be started by U-Boot, directly as part of BOOT.bin, or
via JTAG. Regardless of the exception level at boot, RTEMS will drop to EL1 for
execution. For quick turnaround during testing, it is recommended to use the
U-Boot BOOT.bin that comes with the PetaLinux prebuilts for the board in
question.
